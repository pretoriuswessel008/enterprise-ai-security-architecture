# Module 06 – AI SOC Monitoring & Risk-Based Alerting

## Overview

This module demonstrates security monitoring, detection engineering, event correlation, and risk-based alerting for enterprise AI systems.

Security telemetry generated by AI applications is analyzed to identify suspicious behaviour and convert individual security events into actionable SOC incidents.

The objective is to move beyond isolated alerts and provide contextual detection of multi-stage AI attacks.

## Detection Philosophy

Individual events do not always represent confirmed security incidents.

For example:

```text
Prompt Injection
       +
Sensitive-Data Request
       ↓
Correlated Behaviour
       ↓
Elevated Risk Score
       ↓
Confirmed Incident
```

Correlating related activity provides stronger evidence than treating each event independently.

## Risk-Based Detection

Security events are assigned risk based on their potential impact and relationship to other observed activity.

Security Event
      ↓
Detection Rule
      ↓
Risk Score
      ↓
Correlation
      ↓
Severity
      ↓
Incident

Higher-risk combinations can be escalated automatically for SOC investigation.


SOC Integration

Generated incidents should provide investigators with sufficient context to understand what occurred.

Relevant telemetry includes:

* Timestamp
* User identity
* Source IP
* Event type
* Requested resource
* Risk score
* Severity
* Correlated event history
* Incident classification
* Detection description

## Security Principle

Detection engineering should identify attacker behaviour across multiple events rather than relying exclusively on individual signatures.

Telemetry becomes valuable when it can be correlated into actionable security context.
